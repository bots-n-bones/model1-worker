MODEL_1 WORKER — генерация картинок по подписке Google AI (Flow) для своего сайта
=====================================================================================

ЧТО ЭТО
-------
Исполнитель (worker) на Windows-ПК или Mac превращает подписку Google AI Pro/Ultra в «модель»
для вашего сайта. Сайт складывает задачи в очередь, исполнитель сам их забирает
(сайту не нужно ходить на ваш ПК), генерирует в Google Flow через автоматизацию
браузера (gflow-cli + Playwright + Chrome) и загружает готовые картинки на сайт.

Умеет:
- модель Nano Banana Pro, 1–4 варианта за один запуск;
- до 10 референсов (картинки с сайта), они автоматически пересохраняются в JPEG ≤ 2048 px;
- разрешение 1K или 2K (2K — повышение в том же окне браузера сразу после генерации);
- работа в одном проекте Flow (новый проект — раз в 100 задач);
- обход блокировки Flow по региону (RU/BY) встроен, расширения не нужны;
- из картинок удаляются метаданные (EXIF/XMP/C2PA). Невидимый водяной знак SynthID
  удалить нельзя;
- на сайт уходят только общие коды ошибок, подробности остаются в логах на ПК.

Ограничения:
- задачи выполняются строго по одной (один аккаунт = один профиль браузера);
- время: ~40–60 с на задачу, +8 с на каждый референс, +30–60 с на каждую 2K-картинку;
- это автоматизация потребительской подписки — возможны нарушения условий Google,
  лучше использовать второстепенный аккаунт;
- Flow иногда меняет интерфейс — тогда может понадобиться обновить gflow-cli/патчи.

ЧТО НУЖНО
---------
- Windows 10/11 или macOS, Google Chrome, Python 3.11+ (на Windows при установке отметить «Add to PATH»);
- аккаунт Google с подпиской Google AI Pro (или Ultra);
- свой сайт с backend (в примере PHP 8), доступный по HTTPS.

ФАЙЛЫ
-----
install.ps1              установка (venv, пакеты, создаёт worker_config.json с ключом)
login.ps1                разовый вход в Google в отдельном профиле Chrome
worker.ps1               запуск исполнителя (держать окно открытым)
worker.py                исполнитель (очередь сайта, генерация, 2K, загрузка)
gflow_ext.py             запуск gflow-cli с патчами: обход региона, ввод референсов, 2K
test_pro.ps1             тест: 2 картинки 16:9 без сайта
test_refs.ps1            тест: 2 референса без сайта (нужны jpg в test_pro_out или worker_out)
test_2k.ps1              тест: 2K последней готовой задачи исполнителя без сайта
worker_config.example.json  пример настроек
install.sh, login.sh, worker.sh, test_*.sh  сценарии для macOS
site/MODEL1_SITE_SPEC.md ТЗ для сайта (отдать агенту/разработчику сайта)
site/m1_reference.php    эталонная реализация очереди на PHP

УСТАНОВКА
---------
Распакуйте папку куда угодно (путь без кириллицы лучше), откройте в ней PowerShell.
Если скрипты не запускаются: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

1) .\install.ps1
   Покажет ключ исполнителя (worker_key) — понадобится сайту.

2) Откройте worker_config.json и впишите адрес backend вашего сайта:
     "endpoint": "https://ваш-сайт/backend.php"
     "prompt_suffix": ""      — текст, который добавляется в конец каждого промпта
                                 (необязательно, можно оставить пустым)

3) .\login.ps1
   Откроется Chrome — войдите в Google-аккаунт с подпиской. Окно закроется само.

4) Проверка без сайта: .\test_pro.ps1
   Должны появиться 2 картинки в test_pro_out. Лог — test_pro.log.
   Важно: в Flow должен быть обычный режим ввода. Если в строке промпта включён
   переключатель «Агент» (Agent) — выключите его на flow.google.com (с референсами
   режим «Агент» не работает).

5) Сайт: отдайте разработчику/агенту файлы из папки site\ и ключ исполнителя
   (в приватный конфиг сайта как MODEL1_WORKER_KEY, не в код и не в репозиторий).
   Там описаны 3 служебных действия (m1_next / m1_complete / m1_fail), очередь,
   референсы, разрешение 1K/2K и тексты ошибок.

6) Запуск: .\worker.ps1
   Окно держать открытым. Лог — worker.log, подробности каждой задачи —
   worker_out\<id задачи>\run.log. Запущен может быть только один исполнитель:
   второе окно напишет «another worker is already running» и будет ждать.
   При изменении worker.py исполнитель сам перезапускается.

ЗАПУСК НА macOS
---------------
Нужны Google Chrome и Python 3.11+; если Python не установлен: brew install python@3.12.
Откройте Terminal в этой папке:

  ./install.sh
  отредактируйте worker_config.json: укажите HTTPS-адрес backend сайта в endpoint
  ./login.sh
  ./test_pro.sh
  ./worker.sh

Скрипт установки создаёт venv и worker_config.json с секретным worker_key.
Этот ключ нужно указать в приватных настройках сайта как MODEL1_WORKER_KEY.
Для дополнительных проверок: ./test_refs.sh и ./test_2k.sh [job_id] [index].
Профиль Chrome сохраняется в gflow_home; worker.log и worker_out содержат логи.
Остановить исполнителя: Ctrl+C. Не запускайте тесты во время генерации.

ЛОКАЛЬНО БЕЗ САЙТА (macOS)
-------------------------
Если сайта и backend нет, worker.sh не нужен. После ./install.sh и ./login.sh
откройте двойным щелчком «Локальная генерация.command», введите запрос и нажмите Enter.
Изображения сохраняются в local_out, папка результата откроется в Finder.
По умолчанию используется проект Flow c5ace0b7-be32-4f78-bf95-bfc3c8f415af,
модель Nano Banana Pro, 1 картинка 1:1.
Из Terminal можно задать параметры:
  ./venv/bin/python local_app.py "ваш запрос" --aspect 16:9 --count 2

ЛОКАЛЬНЫЙ САЙТ (macOS)
---------------------
После ./install.sh и ./login.sh запустите ./start_site.sh. Откроется страница
http://127.0.0.1:8766/ без входа, с формой запроса, форматом, 1K/2K и галереей.
Референсы в текущем режиме Flow этого аккаунта не работают; на странице они отключены.
Сервер и исполнитель работают только на этом Mac, пока окно Terminal открыто.
Данные сайта сохраняются в site/local_data. Публичный домен не требуется.
Для локального режима endpoint в worker_config.json должен быть
http://127.0.0.1:8765/backend.php; внешний HTTPS-адрес нужен только для
отдельного сайта в интернете.

ДАШБОРД НА СЕРВЕРЕ, ИСПОЛНИТЕЛЬ НА MAC
--------------------------------------
Сайт (очередь, вход, галерея) живёт отдельно: репозиторий free-banana-studio
на Arcane/Docker. На этом Mac остаётся только исполнитель Google Flow.
В worker_config.json укажите:
  "endpoint": "https://ВАШ-ДОМЕН/backend.php"
  "worker_key": тот же ключ, что STUDIO_WORKER_KEY на сервере
Запуск: «Запустить исполнителя.command» или «Запустить студию.command».
Они не поднимают локальный сайт и туннель, а только worker.py.
Дашборд открывается на сервере и остаётся онлайн, даже если Mac выключен;
новые задачи выполнятся, когда исполнитель снова запустится.

ДОСТУП С ЛЮБОГО КОМПЬЮТЕРА
---------------------------
На Mac достаточно открыть двойным щелчком «Запустить студию.command».
Он сам поднимет локальный сайт, исполнителя и туннель. Ссылка для других
компьютеров появится в Terminal и сохранится в АДРЕС_СТУДИИ.txt. Пока окно
открыто, компоненты автоматически перезапускаются при сбое. Ctrl+C остановит всё.
То же из Terminal: ./start_all.sh. Крышку MacBook не закрывать: caffeinate
предотвращает сон от бездействия, но не сон при закрытии крышки.

ЗАПУСК ТОЛЬКО НА ЭТОМ MAC
------------------------
Откройте двойным щелчком «Запустить студию локально.command» или выполните
./start_local.sh в Terminal. Скрипт запускает сайт и исполнитель Google Flow,
но не запускает туннель. Страница без входа доступна на http://127.0.0.1:8766/ только
с этого Mac. Окно Terminal нужно оставить открытым; Ctrl+C остановит оба процесса.
Оба скрипта запускают один сервер. Для внешней ссылки сохранён вход по паролю.

Альтернативный ручной запуск:
Оставьте локальный сайт и исполнитель запущенными. В другом окне Terminal
запустите ./share_site.sh. Он выдаст временную HTTPS-ссылку localhost.run,
которая открывается на любом компьютере. Логин страницы: studio, пароль
задаётся командой ./venv/bin/python site/set_password.py (показывается один раз).
Ссылка работает, пока запущен share_site.sh, и может измениться при перезапуске.
Компьютер-исполнитель должен быть включён и подключён к интернету.

ВАЖНО ВО ВРЕМЯ РАБОТЫ
---------------------
- Не трогайте окно Chrome, которое открывает исполнитель (не перезагружайте, не кликайте):
  задача сорвётся и пойдёт заново. Смотреть Flow — в своём обычном браузере.
- ПК не должен засыпать, пока ждёте генераций.
- Профиль браузера с входом в Google лежит в gflow_home\ — не передавайте его никому.

НАСТРОЙКИ (переменные окружения, необязательно)
-----------------------------------------------
M1_MODEL               модель gflow (по умолчанию nano-pro = Nano Banana Pro; nano2 — Nano Banana 2)
M1_TIMEOUT             лимит на генерацию, с (600)
M1_UPSCALE_TIMEOUT     лимит на отдельное повышение до 2K, с (180)
M1_PROJECT_MAX_JOBS    сколько задач в одном проекте Flow до создания нового (100)
Удалить worker_meta\project.json — следующая задача начнёт новый проект.

ЕСЛИ ЧТО-ТО НЕ ТАК
------------------
Смотрите worker.log и worker_out\<id>\run.log (в конце — JSON с ошибкой gflow).
- «Profile locked» — профиль занят другим процессом (второй исполнитель, тест, Chrome).
  Найти и закрыть лишние:
    Get-CimInstance Win32_Process -Filter "name='python.exe'" | Where-Object CommandLine -like '*worker.py*' | Select ProcessId, CommandLine
- «Flow isn't available in your country» — в логе должна быть строка
  «[gflow_ext] Flow region check patched». Если её нет — Flow поменял код, нужен новый патч.
- «media-upload-rejected» — Flow не принял файл-референс (обычно уже лечится
  автоматическим пересохранением в JPEG).
- «not ported» / refs_unsupported — включён режим «Агент», выключите его.
- Сессия Google слетела (worker_auth) — снова .\login.ps1.
- Ошибки на стороне сайта (403 и т.п.) — ключ в worker_config.json и на сайте должен совпадать.
